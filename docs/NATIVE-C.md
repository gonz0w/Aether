## Exact bounded implementation

The kernel validates ELF64 LE System V ET_EXEC, x86-64, bounded program headers,
LOAD permissions/overlap, entry, mapped PHDR/TLS and RELRO before launching. Unknown
segments, W+X, out-of-range bytes and page-quota exhaustion are rejected. The initial
native profile narrows the userland host proposal to image bytes below 0x10000000,
128 private pages per instance (512 KiB including stack), 32 page tables and a
64 KiB stack at 0x08000000. Stack/image overlap rejects; unmapped neighbors remain
guards. It does not accept the full 16 MiB host-model image quota or host stack address.

Each root maps only its own user backing. Kernel mappings retain the trusted kernel
image with code/constant permissions and remove writable aliases of both immutable
user images. Boot direct mappings are absent. CR4 global translations are flushed
before entry. Native setup enables x87/SSE context support and retains AVX/XSAVE
as unsupported. Each exception saves FP state; selection restores FP and FS base.
Two different TLS/XMM values survive 64 deliberate context yields each, with PIT
preemption also enabled. This does not establish complete extended CPU-state support.

The private interrupt entry is 0x81, distinct from existing 0x80 contracts. Musl's
internal operation numbers are translated to a separate 0x10000-offset namespace.
No general Linux syscall ABI or production operation allocation is promised:

| Experiment operation | Semantics |
| --- | --- |
| 0x1009e | Set caller FS for ARCH_SET_FS argument; require a mapped writable user address |
| 0x100da | Register a caller-writable 4-byte clear-TID address; return actual fixed instance/thread ID 1 or 2; clear on terminal transition |
| 0x10001 | Write caller FD 1 only when launch grants output; bounded validated copy, max 16 bytes per successful partial transfer, 256-byte request limit |
| 0x100e7 / 0x1003c | Stop this single-thread process, retain status, clear registered address; no return to terminated code |
| 0x1fffe | Fixture yield for independent TLS/FP preservation oracle |
| Other values | Return -ENOSYS; no successful no-op for unsupported behavior |

The FD sink is a bounded 256-byte kernel conformance buffer, not a production
console service. Wrong FD returns -EBADF; inaccessible/overflowing buffer returns

exists, so clear-TID wake semantics for multiple threads are not claimed.

A user fault terminates its instance while the peer continues. Once both are
terminal, both user roots are detached and translations flushed, backing is zeroed
