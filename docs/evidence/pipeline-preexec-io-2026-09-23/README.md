# Scoped descriptor traffic before exec — 2026-09-23

Tracing the actual dash pipeline found a concrete integration mismatch: shell
redirection closes inherited descriptors before exec, while the private replacement
state previously owned that channel exclusively as exec traffic. The older actual-
main fixture uses a different owner; the capacity fixture is not a drop-in shell
runtime. NATIVE-SHELL-STARTUP records the trace and remaining differences in parent
construction, descriptor layout, path/argv selection and wait orchestration.

This change adds opt-in multiplexed intake only while the active, bound replacement
awaits an exec request. The existing dispatcher accumulates a complete frame. Opcode84
enters the existing canonical exec validator; ordinary requests enter the existing
scoped pipe/standard-stream handlers. The validator's phase completion is shared
with the original transport-driven path, avoiding two authorization rules.

The dispatcher retains partial ordinary replies and completes them before reading
another request. Exec replies and subsequent snapshot/freeze/admission/publication,
grant/report/readiness traffic stay exclusively owned by replacement progression.
Later children remain parked. Routing uses the authenticated slot/generation/channel;
frame fields cannot select a different caller. No operation is reapplied while its
reply is being fragmented. Accepted exec transfers channel ownership at a complete
frame boundary; pending descriptor requests cannot spill into snapshot intake.
