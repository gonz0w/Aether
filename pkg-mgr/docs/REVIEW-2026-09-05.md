# Repository review — 2026-09-05

The project has a useful executable fixture and substantial research, but is not yet a usable package manager. This review inspected local code, current and historical planning, Aether's current README/architecture, and sys-init's seed/state. It did not perform a fresh upstream package-manager survey, kernel validation, or a comprehensive security audit.

## Findings

| Priority | Evidence | Implication / next work |
| --- | --- | --- |
| High | `mk/pkg.mk`: `package` lists phases as sibling prerequisites | Parallel make can violate phase order. Establish dependencies before expanding the build path. |
| High | `verify` checks nonempty files; `verify-source-metadata` is a separate target defaulting to the original local source | The package path does not hash-check copied bytes before extraction. Bind verification to the actual consumed artifact. |
| High before installation | `clean` removes caller-configured paths; stage-install accepts arbitrary `DESTDIR` | There is no enforced private-root safety boundary. Current tests pass for their supplied paths, not hostile path input. |
| High before binary delivery | Snapshot helper can return success with a tool-unavailable result | A successful helper exit is not an installation trust decision. Add fail-closed binary eligibility before consuming remote binaries. |
| Medium | `-include`, `$(dir ...)`, and `:=` are present in make files | POSIX-shell intent does not establish portable make syntax. Current review used macOS's GNU Make; BSD make runtime compatibility remains unproven. |
| Medium | Manifest generation uses `find -type f` | Only regular files are represented; link/type/mode semantics are needed before general package ownership or removal. |
| Planning | Five tests refer to `.planning/phases/...` artifacts already moved into completed milestones | These failed before this reset and belong with historical evidence. Six other tests exercise the current code/fixtures. |
| Integration | Aether runs bounded Rust fixtures; sys-init has no established descriptor contract in reviewed material | Start host-side. Do not promise a native package manager, init hook API, or bootable package image yet. |

No implementation fixes were bundled into this documentation reset. The current make/verifier work was already modified or untracked and was preserved. The next roadmap item addresses the build-path gaps.

## Verification

Before migration, all eleven original tests were run sequentially in a temporary copy of the working tree on this macOS host:

- Passed: `distinfo-parser-fixtures.sh`, `phase-2-happy-path.sh`, `phase-3-safety-failure.sh`, and all three `trust-metadata-*.sh` tests.
- Failed: `phase-2-posix-reference-slice.sh`, `phase-3-recipe-spec-readback.sh`, `phase-3-rust-zig-narrow-evidence.sh`, `phase-4-boundary-recommendation.sh`, `phase-4-readiness-synthesis-readback.sh`. Their expected active-phase inputs were absent; these are historical path failures, not newly introduced runtime failures.
- Live minisign signature checks passed. The suite also explicitly tests the tool-unavailable result.

After migration, `sh tests/check.sh` reruns the six active tests in an isolated copy. Shell syntax checks and active Markdown link checks cover the new runner/documentation. Planning-file hashes verify preservation independently of Git rename detection. No Linux/BSD runtime, reproducible build, sandbox confinement, Aether execution, or sys-init activation was proven here.

## Migration decision

The entire former `.planning` tree moved to `docs/archive/2026-09-05-planning-reset/.planning`, with an inventory and hashes. Five stale historical tests moved beside it. The new active planning surface has three files; README is the entry point and architecture holds cross-project contracts. AGENTS now points to that system. The previous state-model work remains useful input, but its four-phase generation/GC program no longer controls development.

Old backlog themes are retained in ROADMAP without the retired promotion gates. No old research was declared invalid merely because it was archived. The sibling repositories were read only and their separate workflows were not changed.
