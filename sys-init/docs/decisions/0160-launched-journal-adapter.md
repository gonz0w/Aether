# 0160 — Launched-cut journal adapter

BG-057, 2026-09-07. First real policy-model/journal integration, not native execution.
Add JournalRuntime.reserve_batch/cancel_batch/batch_reserved using its actual
EventJournal ticket and existing Model.batch path. Prepared capacity blocks other
runtime commands. Consume the reservation once; failure after attempted application
closes the runtime and preserves diagnostic prepared/cut state. Normal unprepared
runtime behavior stays unchanged.

A bounded LaunchedAdapter accepts at most two exact fixture Source objects mapped
to actual retained executed launch-effect tokens through an explicit injective
symbol encoding. It supports only starting -> started Launched observations at
unchanged model time, not Terminal/Cleaned or readiness. Revalidate epoch/revision,
service/generation, full token and launch state before Model.batch. Bind observation
receipt to the actual reserved journal serial, and verify transitions plus complete
generated effect capture before returning it. A dependency launch generated by the
cut must remain a reserved real journal obligation, not an invented fixture reply.

Test actual dependency activation/capture, busy journal with unchanged model,
prepared command denial/cancellation, wrong source token, skipped transition,
capture failure and distinct observation/journal serials. Preserve coordinator
replay no-op. Mutation controls must detect skipped transition verification and
skipped journal capture verification through the adapter's real call path.
Run full local gates, retain exact inputs/results. Actual native origin, confirmed
native launch outcome, Terminal/Cleaned mapping and resource cleanup stay follow-ons.
O/I/E scope and Distribution exclusions remain; no shared pins or native bytes change.

Review refinement: JournalRuntime's prepared-batch API explicitly rejects derived
runtime profiles. In particular QueuedRuntime.batch performs intake rather than
application, so inheriting this entry without rejection would leak a reservation
and misrepresent completion. A new regression requires unchanged queue/model/journal
state on that denial. The prior 262-test passing snapshot is retained; the final
suite has 263 tests, including nine Launched-adapter cases and two source controls.
