# Planning documents and work routing

Read the pinned [method](../../.agent-temper/METHOD.md), root
[PROJECT](../../PROJECT.md#public-onboarding-cutover) and the
[GitHub work profile](../../.agent-temper/profiles/github.md). Issues become the
sole live work authority only after verified onboarding and migration. Until
that cutover the one approved bootstrap record owns onboarding; these files do
not select new public implementation work.

After cutover read the whole owning issue and discussion before acting. It owns
finite scope, non-goals, prerequisites, acceptance, owner, actual status, checks,
review and continuation. Preserve BG/question IDs when linking prior material.
Root STATE is compatibility navigation, not a selector or duplicate status view.

## Durable documents

- PROJECT records component product direction and success criteria.
- ROADMAP records capability gates, not an executable queue.
- Architecture/specification documents define interfaces and ownership.
- Cited research belongs in `docs/research/`; decisions in `docs/decisions/`.
- Dated evidence records keep their original input and claim scope.

Legacy STATE, `backlog/PRIORITY.md`, captured/active/archive story files and memory
question files are read-only historical context in the public snapshot. Their
folder, old status or next-action wording is not current authorization. Do not
move stories through those folders as a new workflow, reorder their old priority
list, or copy issue status back into them. The maintainer may add links to their
canonical issues without creating a second queue.

Define expected results, forbidden outcomes and checks before implementation;
prefer meaningful test-first evidence and record justified alternatives honestly.
Follow root DEVELOPMENT for focused checks, frozen sources and compact results.
Cited research and bounded follow-up issues precede research completion. Missing
required native inputs/reviews remain blocked; host success is not native or
release acceptance. Onboarding changes no execution or resource approval.

Read STANDARDS, EXPERIENCE and DISTRIBUTION for applicable pinned requirements.
Shared normative changes remain owned by the separate local standards project;
this consumer does not silently replace a pin or publish that project. Old slash
commands and phase generators stay retired. No extra workflow plugin is required.
