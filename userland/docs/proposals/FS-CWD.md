## Requirement and interface

Each of the existing four ProcessFiles records retains its actual service CWD.
None denotes the borrowed delegated root; Some holds a connection-scoped directory
handle already owned by this client. New admitted shell starts at that root.
Under an exclusive borrow, change_directory(process,path) prepares a new directory
handle, releases the old handle only when no other admitted record references it,
then publishes the new selection. The caller supplies an authenticated opaque
Process key; path strings/UID/PWD/HOME cannot admit a process or grant authority.

Accept a nonempty canonical path of at most255 bytes. Absolute paths start at the
delegated read-only root; relative paths start at that process's retained CWD.
'/' selects the borrowed root and '.' leaves the exact CWD unchanged. Dotdot and
embedded dots, NUL, repeated/trailing separators and malformed paths remain
unsupported and reject; no lexical fake-parent traversal or synthetic getcwd.
The eventual public POSIX binding must define parent/symlink/rename/getcwd semantics
before selecting this state. File open_read uses the same absolute/relative base
selection and existing directory walks, FD preflight and error/offset handling.

Fork inherits the same directory binding without another remote handle or a
reference counter. Subsequent chdir changes only that process's reference. Preserve
CWD across successful exec/CLOEXEC processing; known failed exec/copy preserves it,
unknown native copy retires admission without pretending the child settled. A
settled process releases its CWD only after exact native settlement and FD aliases
are settled. Keep occupancy on a failed last close; retire the shared source,
never replay, reconnect or publish a prepared directory after uncertain cleanup.
All references are computed from the same four records. The root is never closed
as an ordinary directory handle. Serial process generations remain nonreusable.
