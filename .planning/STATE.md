# Public work navigation

## System work index

This compatibility index holds navigation, not live status or priority. Apply
[PROJECT's cutover rule](../PROJECT.md#public-onboarding-cutover): Issues become
the sole live work authority only after verified onboarding and migration are
recorded. Repository creation, issue links in a draft or a CI result alone do not
establish that cutover. Until then the one approved onboarding bootstrap record
owns that operation; do not start public implementation from historical queues.

- [GitHub Issues](https://github.com/gonz0w/Aether/issues): live scope, ownership,
  dependencies and continuation after cutover.
- [Engineering policy](../PROJECT.md) and [GitHub operation](../docs/GITHUB.md):
  activation, review, source publication and checkout boundaries.
- [Product intent](PROJECT.md), [architecture](../docs/ARCHITECTURE.md) and
  [ROADMAP](ROADMAP.md): durable goals, contracts and capability gates.
- Component [userland](../userland/README.md), [sys-init](../sys-init/README.md)
  and [pkg-mgr](../pkg-mgr/README.md) guides: responsibility and scoped commands.

## Historical records

Component STATE/BACKLOG/PRIORITY files and legacy work records preserve stable
UL/BG/package IDs, decisions and dated observations. They are read-only context,
not a second queue or current assignment. Canonical issues may link them without
copying mutable status back into Markdown. Historical next-action text does not
authorize work or renew a consumed native disposition.

The public snapshot excludes local qualification receipts, SDK/image bundles and
the obsolete whole RC1/ADP-01 packet. A historical summary or hash cannot replace
missing bytes, required execution or review. No public replay, native acceptance,
private-history publication or AF09 completion is claimed by this index.
